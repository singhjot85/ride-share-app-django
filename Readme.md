# LoadShare

Route-based logistics with heavy freight capacity sharing.

LoadShare connects heavy-vehicle drivers who already run fixed routes across India with senders who need parcels moved along those routes. Drivers publish the routes they are going to drive, senders request delivery, and the system matches parcels to routes with spare capacity.

> **Status:** Proof of Concept (POC). The scope, stack and limits below describe the POC only.

## How It Works

1. **Driver publishes a route** - origin, destination, schedule and spare capacity.
2. **Sender requests a delivery** - pickup, drop-off and parcel details.
3. **System matches** the parcel to routes that pass near both points.
4. **Driver accepts**, carries the parcel and shares live location.
5. **Sender tracks** the parcel until delivery and receives a receipt.

## Tech Stack at a Glance

| Layer | Choice |
| --- | --- |
| Backend | Django, Django REST Framework, GeoDjango |
| Async jobs | Celery + Celery beat (Redis broker) |
| Database | PostgreSQL + PostGIS |
| Cache / latest driver location | Redis |
| Driver app | Native Android (Kotlin, Jetpack Compose) |
| Sender web | React + TypeScript (Vite), Hindi and English |
| Ops panel | Django admin |
| Maps | Leaflet or MapLibre + a tile provider |
| Routing engine | OpenRouteService (HGV profile) to start |
| Push / SMS / Payments | FCM / MSG91 / Razorpay (test mode) |
| Deployment | Docker Compose on a single EC2 VM (ap-south-1) |

Reserved for after the POC: Sentry error tracking, S3 file storage, automated daily Postgres backups.

## Out of Scope (for now)

Kubernetes, Kafka, WebSockets (polling first), third-party KYC, escrow and payouts, ratings, iOS, and all ML/DL.

## Getting Started

Prerequisites: Docker and Docker Compose.

```bash
git clone <repository-url>
cd loadshare
cp .env.example .env        # fill in the required values
docker compose up --build
```

See [backend/README.md](backend/README.md) and [frontend/README.md](frontend/README.md) for running each part on its own.
